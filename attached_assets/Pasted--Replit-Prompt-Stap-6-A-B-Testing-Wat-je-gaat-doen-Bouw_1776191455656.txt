## 1. Database — uitbreiding bestaande tabellen

Voeg de volgende kolommen toe aan de `campaigns` tabel als ze nog niet bestaan:

```sql
ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS ab_winnaar_variant TEXT;
-- opties: null (nog niet bepaald), 'A', 'B'

-- timestamp waarop de winnaar automatisch is gekozen

ALTER TABLE campaigns ADD COLUMN IF NOT EXISTS ab_test_fase TEXT DEFAULT 'test';
-- opties: test (bezig met splitverzending), bepaling (winnaar wordt bepaald), 
--         doorgestuurd (winnaar naar rest gestuurd), voltooid
```

Voeg toe aan `mail_sends`:
```sql
ALTER TABLE mail_sends ADD COLUMN IF NOT EXISTS is_ab_test_send INTEGER DEFAULT 1;
-- 1 = onderdeel van de A/B test split
-- 0 = winnaar-verzending naar de rest van de lijst
```

## 2. A/B test verzendlogica — uitbreiding op stap 4

Pas de `sendCampaignBatch` functie uit stap 4 aan voor A/B campagnes:

### Fase 1: Test split verzending
```
1. Haal alle matchende contacten op (op basis van segmentfilters)
2. Filter uitgeschreven/geblokkeerde contacten eruit
3. Schud de lijst willekeurig door elkaar (shuffle)
4. Bereken split:
   - Aantal voor variant A = Math.floor(totaal * (ab_split_pct / 100))
   - Aantal voor variant B = totaal - aantal_A
   - MAAR: stuur de test alleen naar een deel van de lijst
     - Testgroep = Math.min(totaal, Math.ceil(totaal * 0.4))
     - Max 40% van de totale lijst doet mee aan de A/B test
     - De overige 60% wacht op de winnaar
     - Uitzondering: als totaal <= 20 contacten, stuur A/B test naar iedereen
5. Wijs variant toe:
   - Eerste helft van testgroep → variant A (is_ab_test_send = 1)
   - Tweede helft van testgroep → variant B (is_ab_test_send = 1)
   - Rest van de lijst → nog geen mail_send record (wacht op winnaar)
6. Verzend de testgroep via sendSingleMail
7. Update campagne ab_test_fase naar 'test'
8. Plan de winnaarbepaling: sla op wanneer de winnaar bepaald moet worden
   (ab_winnaar_na_uren uur na de eerste verzending)
```

## 3. Automatische winnaarbepaling

### Scheduler uitbreiding
Voeg toe aan de bestaande scheduler (elke 5 minuten check):

```javascript
async function checkABWinners() {
  // Haal alle campagnes op waarbij:
  // - ab_test_actief = 1
  // - ab_test_fase = 'test'
  // - eerste verzending was meer dan ab_winnaar_na_uren uur geleden
  
  for (const campagne of campagnes) {
    await bepaalABWinnaar(campagne.id);
  }
}
```

### `bepaalABWinnaar(campaignId)`
```
1. Haal statistieken op voor variant A en B uit mail_events:
   
   Voor elke variant:
   - verzonden = COUNT mail_sends WHERE variant = X AND is_ab_test_send = 1 AND status = 'sent'
   - geopend = COUNT DISTINCT mail_send_id FROM mail_events 
               WHERE type = 'open' AND mail_send.variant = X AND mail_send.is_ab_test_send = 1
   - geklikt = COUNT DISTINCT mail_send_id FROM mail_events 
               WHERE type = 'click' AND mail_send.variant = X AND mail_send.is_ab_test_send = 1
   - open_rate = geopend / verzonden
   - click_rate = geklikt / verzonden

2. Bepaal winnaar op basis van ab_winnaar_op instelling:
   - 'open_rate': winnaar = variant met hoogste open_rate
   - 'click_rate': winnaar = variant met hoogste click_rate
   - Bij gelijke stand: winnaar = variant A (default)

3. Minimale drempel: als beide varianten 0% hebben (niemand heeft geopend/geklikt),
   wacht dan nog eens ab_winnaar_na_uren uur voor een tweede check.
   Na twee checks zonder resultaat: kies variant A als winnaar.

4. Sla winnaar op:
   - UPDATE campaigns SET ab_winnaar_variant = 'A' of 'B',
     ab_winnaar_bepaald_op = NOW(),
     ab_test_fase = 'doorgestuurd'

5. Stuur winnaar naar de rest van de lijst (verstuurWinnaarNaarRest)
```

### `verstuurWinnaarNaarRest(campaignId, winnaarVariant)`
```
1. Haal alle contacten op die voldoen aan segmentfilters
2. Filter contacten die al een mail_send record hebben voor deze campagne eruit
3. Maak mail_send records aan voor overgebleven contacten met:
   - variant = winnaarVariant
   - is_ab_test_send = 0
4. Verstuur in batches van 50 (zelfde als stap 4)
5. Update campagne status naar 'voltooid' na verzending
6. Stuur notificatie naar de gebruiker (zie sectie 7)
```

```
[Bekijk resultaten →]
```

Sla notificaties op in een aparte tabel:
```sql

  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL,           -- ab_winnaar, campagne_voltooid, etc.
  titel TEXT NOT NULL,
  bericht TEXT NOT NULL,
  link TEXT,                    -- bijv. /campaigns/123
```

- Badge met aantal ongelezen notificaties (rood bolletje)

## 8. A/B test voor flows (uitbreiding stap 5)

Voeg A/B test toe aan e-mail nodes in de flow builder:

In het eigenschappenpaneel van een e-mail node:
- Toggle: "A/B test voor deze stap"
- Bij activatie: twee tabbladen verschijnen (Variant A / Variant B) in de node
- Split instelling: slider 50/50 (of aanpasbaar)
- Winnaar bepalen na: X uur (instelbaar)
- Winnaar op: open rate / click rate

De flow engine verwerkt dit als volgt:
- Bij bereiken van de e-mail node: stuur variant A of B op basis van willekeurige split
- Sla op welke variant het contact ontving in flow_contact_progress (extra kolom `ab_varianten` als JSON)
- Winnaarbepaling werkt zelfde als bij bulk campagnes maar dan per flow-stap

## 10. Validatie & randgevallen

Behandel de volgende randgevallen correct:

- **Te weinig contacten**: Als totaal < 10 contacten, schakel A/B test automatisch uit en stuur iedereen variant A. Toon waarschuwing: "Te weinig contacten voor een betrouwbare A/B test. Variant A wordt naar iedereen gestuurd."

- **Gelijke stand**: Bij exacte gelijkstand altijd variant A kiezen als winnaar.

- **Campagne gestopt tijdens test**: Als een campagne gestopt wordt terwijl de A/B test loopt, stuur geen winnaar meer. Toon in rapportage: "Campagne gestopt — geen winnaar bepaald."

- **Variant B zonder inhoud**: Als variant B geen content heeft maar A/B test staat aan, toon foutmelding bij activatie: "Variant B heeft nog geen e-mailinhoud. Vul variant B in via de e-mail builder."

- **Meerdere opens per contact**: Tel elke unieke contact slechts één keer mee voor open rate berekening (gebruik DISTINCT mail_send_id).
